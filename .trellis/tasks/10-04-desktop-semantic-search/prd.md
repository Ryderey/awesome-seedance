# Desktop semantic search relevance

用户反馈：搜索“我想拍一个运动饮料广告”，Agent 推荐了健身、骑行视频，并在理由中承认缺少饮料产品。用户要求先分析原因和写方案，考虑预先分类标记，再交给 Agent 匹配。随后明确：应由 Agent 分析输入并确定搜索关键词；应预注入职责与工作步骤提示词。

用户已确认“好的，按方案完成任务”，授权按完整方案实施。交付固定职责提示词、Agent 搜索计划、证据语义索引、结果分层、回归验证和可运行便携版。真实供应商评测须使用明确提供的测试配置，不能将模拟接口测试当作真实模型准确率；提交/推送留在实现验证之后。

期望后续行为：Agent 先理解主体与用途、生成关键词和条件；程序按该计划检索；Agent 使用候选的真实内容和标记核对排序。默认产品案例需有主要产品和用途依据，纯技巧参考明确区分。保留完整本地探索、未知处理和无匹配诚实输出。

计划与完整草案：PLAN-desktop-agent-search-relevance-2026-10-04.md。研究：research/catalog-semantics.md。

验收：运动饮料广告默认不推荐纯骑行/健身案例；汽水和果饮广告只能作为相关产品；运动饮料不自动要求运动场景。显式骑行查询仍能匹配骑行案例。全部 27 模板/670 案例拥有带来源指纹的索引项，信息不足标记 unknown；保留六条未分配案例、全部本地结果、自定义请求头和取消/重试/复制行为。离线与真实供应商评测分开记录。
