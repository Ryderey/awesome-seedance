# Component guidelines

Use app.js node()/button() helpers and textContent/replaceChildren for library and model text. Never interpolate those values with innerHTML. Card headings use actual local titles. Poster images load lazily; video loads only inside the detail dialog. Source media is the default and retests are explicitly labelled. Close pauses and removes the video src. Error/absent media shows available literal URLs and record-derived link buttons.

Native dialogs provide Escape/focus behavior. CSS uses warm light/charcoal/teal, flat surfaces and reduced-motion handling. Cases appear in increments of 12; the main process must return every locally matched card for browsing, not a permanently truncated first page. Full original prompt and template copyPrompt are different copy actions.

Agent cases use separate topic/related_product/technique/uncertain sections and concise source quotes/gaps. Empty confirmed-theme results are explicit. The small expand-techniques action requests additional transferable techniques; ordinary source switches never call the model. Local exploration keeps its flat grid and unjudged label.

Reuse the inline clarification panel for at most two questions. Show server-provided round/limit, concise prior question/answer context, 2–4 choices, free-text reply and skip-to-broad-reference action. While waiting, no SDK request runs. Duplicate reply/skip clicks must not start duplicate searches or append duplicate history. Broad Agent results are labelled 宽泛参考/信息不足 in the source button, status and note; do not label them precise topic matches. All model question/answer text uses safe DOM/textContent.

While a dialog is open, `html:has(dialog[open])` locks background scrolling. The detail panel owns the single vertical scroll; full prompt blocks expand naturally and never create nested scrollbars. Use overscroll containment on dialogs. The Electron UI smoke checks both case/template details, narrow windows and restoration of the background scroll position after Escape.

Model settings retain the basic fields and use a native details element for advanced headers, collapsed whenever the dialog opens. Build header rows with DOM nodes, fixed/session type selection, enable and plaintext-remember checkboxes. Import shared validation from ../headers.mjs via the module script; show row errors with aria-describedby and disable save/probe while invalid. Session fields display an automatic-value hint, not a generated ID. Explicitly register shared modules in desktop/package.mjs.

Advanced settings also expose single-request waiting time in seconds (1–120, millisecond precision). Restore the saved value when opening or saving settings; invalid input disables save/probe and has its own aria-described error. Label it per request because intent/ranking/repair have separate timers. The application error message must not ask users to adjust a setting absent from the UI.

Advanced generation limit is optional (blank follows the platform default); show the max_tokens/max_completion_tokens selector only when a manual cap is present. Thinking inherits by default, with three explicit none/high/max modes labelled off/on/maximum and their parameter values. Restore/validate these fields and disable them while saving/probing. The native form uses novalidate with explicit settingsSave reportValidity after advanced validation so an invalid control in closed details can be revealed and focused. No context-capacity selector or automatic per-effort quota is introduced.
